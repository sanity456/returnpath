Title
ReturnCustodyRoute - Four-Role Return Custody Workflow

Notes / Description
Built ReturnCustodyRoute, a reusable non-payment return route that maps items to policy windows, then enforces merchant authorization, buyer handoff, carrier acceptance, warehouse receipt, and consensus image comparison. Its distinct GenLayer-native mechanism is semantic category lookup + deterministic window -> ordered four-role custody -> two-image condition-change consensus. Correction applied: Both nondeterministic decisions now pass through the same closed-domain canonicalizers in the validator and again after consensus, so an out-of-domain leader value cannot reach custody state. The full selected set was checked against both steward findings: substantive leader payloads must bind every derived digest, mask, and state field, while operational registries must be owner-scoped or safely reclaimable. No web collection. Policies, categories, references, custody notes, and images are public caller-provided data and are not authenticated. It creates no return right, compels no merchant, moves no money, proves no custody fact, and assigns no liability. GenVM lint and strict typecheck pass; 12 direct tests and 1 five-validator GLSim integration test pass. A fresh repository-specific external wallet set was used, with no workspace, other-owner, or cross-repository wallet reuse. The StudioNet workflow finalized successfully in 9 transactions. The deployed source was read back byte-for-byte, the complete deployed schema matched abi.json exactly, and mechanism-specific terminal state was read back. The current release is commit 7b747ab7ccefd0d90b3cc5718542d6e09b65fb3d; contract source: https://github.com/sanity456/returnpath/blob/7b747ab7ccefd0d90b3cc5718542d6e09b65fb3d/contracts/return_custody_route.py.
